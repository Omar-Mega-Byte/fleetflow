This is a repository review and exercised local boundary, not a public deployment penetration test. ## Registered route and object scope matrix

The rows below cover the controllers under `src/main/java/com/fleetflow`, plus Actuator. `401` means absent/invalid JWT on protected routes; `403` means a valid actor lacks the role or is deactivated. `404` is deliberately shared by unknown and foreign object IDs where an object scope applies. The dispatcher is a global operational role in this synthetic deployment; there is no tenant ID to check on those routes. The rate classes refer to [the fixed-window policy](RESILIENCE.md): `R` read, `E` expensive read, `C` command, `S` stream, `L` location/heartbeat service budget, and `F` local fixture exemption. Protected routes are correlated in request logs; durable state changes also write lifecycle/assignment/outbox history as applicable.

The explicit route allowlist ends in `denyAll`. `LocalApiBoundary` also refuses local/test fixture profiles unless the process binds a loopback address. `DefaultProfileRoutesTests` and `ProdProfileRoutesTests` check unsafe intake/fixture absence. The relevant signed and negative tests are `Phase2SecurityTests`, `KeycloakProviderTests`, `Phase3LifecycleTests`, `Phase4LocationTests`, `Phase6AssignmentTests`, `Phase7RecoveryTests`, `Phase8AsyncEventsTests`, `Phase9TrackingTests`, and `Phase10ZoneTests`. They cover issuer, audience, expiry, signature, role revocation, inactive actors, foreign orders, exact active branch membership, self-only driver routes, zone membership/version changes, tracking privacy, and race/rollback invariants. A complete test of every route/profile/role combination remains open.

On 2026-10-08, `KeycloakProviderTests#disablingProviderUserRequiresLocalActorDeactivationToRevokeIssuedJwt` passed with a real Keycloak container and PostgreSQL actor. An already-issued, valid JWT still returned HTTP 200 after the Keycloak user was disabled; deactivating the corresponding FleetFlow actor then returned HTTP 403 for that same JWT. Local JWT validation does not introspect the provider on each request. For immediate access removal, operations must deactivate the FleetFlow actor as well as disabling the provider user; otherwise the existing token can work until its expiry. The focused class passed 3 tests, 0 failures.

## Review findings and disposition

| Area | Observation | Disposition |
| --- | --- | --- |
| Authentication | Nimbus validates JWKS signature, exact issuer and audience, subject, expiry, and no timestamp skew. PostgreSQL actor/role lookup is per request. No client-supplied actor header is trusted. | Existing signed and negative tests; retain for local target. |
| Request signing and replay | Business calls use provider-signed bearer JWTs; there is no separate per-request HMAC. Server-side lifecycle guards, version checks, and PostgreSQL unique constraints reject conflicting repeated commands; the outbox consumers deduplicate by `(consumer_name,event_id)`. | A valid stolen bearer token can be replayed until expiry, and not every command has a client idempotency key. Do not claim universal replay prevention; transport TLS and token custody are required for any external deployment. |
| Authorization/privacy | Customer orders and tracking use owner scope; merchant actions check exact current branch membership; driver operations use the actor's own driver row; dispatcher is global. Tracking omits stale/reassigned coordinates; notification recipients are actor-scoped. | Existing tests exercise the main negative paths. Full route-by-route and multi-role review remains open. |
| Input/injection | JSON requests bind to explicit DTOs, order list sort fields are allowlisted, JDBC uses parameters for untrusted values, geometry and location have domain validation, and API errors suppress SQL/exceptions. | No obvious injection or mass-assignment path in the reviewed controllers/services. No dedicated DAST or fuzz run. |
| CORS, CSRF, forwarding, headers | The API is stateless bearer-only and CSRF is disabled deliberately; there is no application CORS allowlist for browser credential sharing, nor a configured trust policy for reverse-proxy forwarded identity headers. Spring Security's default response headers apply. | The local loopback demo has no browser session or proxy trust boundary. Define explicit origin, TLS termination, trusted proxy, and header policy before an external browser or ingress is introduced. |
| Secrets/backup | `.env*`, private keys, logs, and archives are ignored; AES-256-GCM protects the archive, and local/decrypted/remote-retrieved hashes are compared. The key lives outside Git. | GitGuardian and final tracked-file checks are separate evidence. The remote credential currently fails, so remote custody/permissions are unverified. |
| Recovery verification | The signed verifier formerly selected a synthetic order without checking the Keycloak user's email or pre-backup state. Restore output also mislabeled a localized timestamp as UTC. | Fixed: require `@example.invalid`, assert `CONFIRMED` before cancellation, preserve the manifest's UTC timestamp string, and fail early on missing recovery configuration. Two fresh unattended runs exercised the path. |
| Compose secrets | Compose requires the `KC_ADMIN_PASSWORD` variable to exist, but its current interpolation accepts an empty value. The unattended restore preflight rejects an empty value. | Keep this as a configuration gap for direct Compose starts; set a strong private value and add a check that does not put a password-shaped placeholder in committed Compose history. GitGuardian flagged the attempted interpolation-only change as a generic password, so that change was removed from this PR's rewritten commits. |
| HTTP/infrastructure | Host ports bind loopback; app image runs as a non-root user; images use digests; no privileged containers; readiness includes DB and Redis while liveness is separate. Keycloak `start-dev`, plaintext internal Kafka, and anonymous metrics inside the monitoring network fit only the synthetic workstation boundary. | Public TLS/proxy hardening, private network segmentation, and broker authentication are release blockers for any public deployment. No global JSON body cap or universal per-route timeout was proved. |
| Operational routes and logs | Default-deny business allowlist, role-gated `/actuator/metrics`, private monitoring-only Prometheus port, and hidden health details were inspected. Correlated JSON request/outbox logs use safe IDs rather than bearer tokens or raw coordinates. | The monitoring port is anonymous to peers on its Compose network; browser dashboard panel rendering and external log retention/access enforcement were not audited. |
| Database | Flyway validates all 12 migrations; transactional outbox and uniqueness constraints protect durable transitions. Compose PostgreSQL uses one full-privilege application credential. | Least-privilege DB roles and automated backup retention/failure alert remain open before a production target. |
| Dependencies/CI | Maven uses Spring Boot parent 4.1.1 and springdoc 3.1.0; images are digest pinned. CI grants `contents: read`, checkout disables persisted credentials, and no untrusted PR code runs with write credentials, but GitHub action tags are mutable. GitGuardian checks run on PRs. | No complete resolved-tree CVE/SBOM scan was available in this environment; the GitHub Dependabot alerts API returned 404 to this credential, so it supplied no finding or clean bill. Review current advisories and pin action SHAs before a public release. Keycloak 26.7.5 carries additional security fixes after the pinned 26.7.4; evaluate applicability and rehearse backup compatibility before changing the pinned identity image. See [Keycloak's release note](https://www.keycloak.org/2026/09/keycloak-2675-released). |

### Resolved Maven advisory scan, 2026-10-08

The first [OSV-Scanner v2.6.0](https://github.com/google/osv-scanner/releases/tag/v2.6.0) source scan resolved the Maven project and reported six affected dependency coordinates: Tomcat core 11.0.24, Jackson 2.21.5 core/databind, Jackson 3.1.5 core/databind, and Kafka's transitive `at.yawk.lz4:lz4-java` 1.10.1. The private JSON report is outside Git at `%LOCALAPPDATA%\FleetFlowPhase11\osv-source-20261008.json`. The scanner executable's SHA-256 was checked against the official release asset digest before execution. This is package advisory matching, not an exploitability finding for each code path.

`pom.xml` now overrides the Spring Boot managed Tomcat version to 11.0.25, the Jackson 2 BOM to 2.21.7, the Jackson 3 BOM to 3.1.7, and the transitive LZ4 library to 1.11.4. `mvn dependency:tree` confirmed all six resolved coordinates use those versions. A second `osv-scanner scan source -r . --format json` returned exit 0 with zero affected packages; the private report is `%LOCALAPPDATA%\FleetFlowPhase11\osv-source-remediated-20261008.json`. A repeat with `--all-packages` enumerated **208 resolved packages and zero affected packages** in `%LOCALAPPDATA%\FleetFlowPhase11\osv-all-packages-20261008.json`. This scan queries currently known OSV advisories for the resolved Maven tree. Container images, runtime configuration, and advisories published later remain separate checks. The old “no complete scan” statement in the table above describes the 2026-10-07 review snapshot; this section supersedes it for Maven dependencies.

After these overrides, local `clean verify` passed 122 tests with zero failures/errors/skips. A rebuilt Compose app on the disposable restored project ran a 62-request Keycloak-signed preflight with 50 HTTP 200, 12 HTTP 204, and zero unexpected errors; the private readiness endpoint returned `UP` and all 66 outbox events were `PUBLISHED`. This exercises the patched runtime on the local synthetic stack, not an external deployment or image vulnerability scan.

The first OSV-Scanner image scan of the rebuilt local app image found Alpine `zlib` 1.3.2-r0 affected by `ALPINE-CVE-2026-85091`; the scanner reported 1.3.2-r1 as fixed. The pinned Eclipse Temurin base digest still contained r0, while the Alpine v3.24 package index offered r1. `Dockerfile` now installs exactly `zlib=1.3.2-r1` from that pinned base. `apk list -I zlib` in the rebuilt app container confirmed r1, and `osv-scanner scan image fleetflow-phase11-replay-app:latest --format json` then returned exit 0 with zero affected packages. The private before/after reports are `%LOCALAPPDATA%\FleetFlowPhase11\osv-app-image-20261008.json` and `osv-app-image-remediated-20261008.json`. A further 62 signed requests succeeded with the patched image, followed by readiness `UP` and all 66 outbox rows `PUBLISHED`. This is a scan of the FleetFlow app image only; Keycloak, PostgreSQL/PostGIS, Redis, Kafka, Prometheus, and Grafana images were not scanned in this exercise.

No frontend package manifest exists in this backend repository. The local demo uses synthetic users and addresses; its Compose ports and developer Keycloak configuration must never be represented as internet-facing production hardening.
