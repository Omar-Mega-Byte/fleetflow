33. **Schedule encrypted off-host backups.** Configure [backup.sh](../ops/production/backup.sh) with the private env, age public recipient and dedicated rclone destination. Run it once, independently list/retrieve the encrypted object and verify its SHA-256; then schedule it twice daily with systemd outside demo windows. The script stops edge, app and Keycloak briefly. Follow [RESTORE.md](../ops/production/RESTORE.md#recovery-set-creation); one manual success is not a sustained RPO.
34. **Prove backup alerts.** Schedule [check-backup-age.sh](../ops/production/check-backup-age.sh) at least daily and connect service failures, missed execution, failed upload/integrity and marker age over 24 hours to the approved receiver. Deliberately trigger and clear each path, retaining the received notification and timestamps. Use [Phase 10 tests](phases/production/phase-10-target-operations-backup-and-recovery.md#tests-required).
35. **Restore on a fresh target.** Create a new isolated Azure VM/Compose project with empty volumes and no source disk. Independently retrieve the encrypted backup and hash, obtain the offline age identity, decrypt, inspect contents, restore both PostgreSQL databases and start only the recorded digests. Verify Flyway/PostGIS, Keycloak subjects, actor mappings, orders, outbox/dedupe and one signed workflow using [the exact restore procedure](../ops/production/RESTORE.md#isolated-restore-rehearsal). Never test by overwriting the live volumes.
36. **Measure RPO and RTO from data and functionality.** Record the latest committed synthetic event recoverable from the backup and the loss window (RPO), plus restore start to successful signed public workflow (RTO). Require RPO ≤24 hours and RTO ≤1 hour, with timestamps and evidence. A backup frequency or container health result is not the measured value. Use [Phase 10 exit criteria](phases/production/phase-10-target-operations-backup-and-recovery.md#exit-criteria).
37. **Run the 30-minute external qualification.** Prepare a target-safe runner first: [Phase 11 target qualification](operations/PHASE11_TARGET_QUALIFICATION.md#target-runner-blocker) explains why `scripts/Phase11-Breadth.py` must not be pointed at public Azure unchanged. Keep admin ports private, provision short-lived synthetic credentials, then run ≥1,800 seconds from outside the FleetFlow VM with two reviewer sessions, ten drivers, ten SSE streams and ≥100 expected operations. Record success for expected approvals/rejections, p50/p95/p99 non-stream API latency, error classes, CPU/RAM/GC, DB pool, Redis, Kafka/outbox and SSE; require ≥99% expected outcomes and p95 ≤1 second.
38. **Exercise failure, cold start and spend.** In a planned window run the bounded DB/Redis/Kafka/Keycloak/app restart, slow-stream, disk/backup-alert and rollback/forward-fix cases from [Phase 11](phases/production/phase-11-target-performance-and-failure-qualification.md). Confirm alert fire/clear, state integrity and no duplicate effects. Time a deallocated VM from the start command to a usable signed public workflow (≤15 minutes), and compare actual Azure cost with the approved budget. Re-run affected gates after any fix or SKU change.
39. **Assemble one evidence pack and test the reviewer guide.** Make a dated, immutable, secret-free manifest listing final `main` SHA and CI, six manifest/config digests, full advisory review, Azure IDs/cost, DNS/TLS/OIDC/network/persona evidence, backup/alerts, fresh restore and RPO/RTO, 30-minute metrics, failure/cold-start results and file SHA-256 hashes. Update the [README](../README.md) and reviewer guide with the real URL, on-demand schedule, safe credential retrieval, five synthetic role scenarios, expected denials and single-VM limit. Test only those instructions in a fresh browser profile with no operator help. Follow [Phase 12](phases/production/phase-12-final-public-demo-acceptance.md).
40. **Record the final decision.** The release owner checks every P0 item in the [roadmap release gate](PRODUCTION-ROADMAP.md), verifies the evidence belongs to one final commit/image set/Azure target, then signs exactly `APPROVED FOR ON-DEMAND PUBLIC DEMO` or `REJECTED — NOT READY`, with date, owner and residual risks. Update phase/roadmap statuses to match the result. Share the URL only after approval. This marks completion for the synthetic public-demo scope; commercial service remains a separate decision.
